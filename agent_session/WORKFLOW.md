# Coding-agent workflow and project prompts

This is an English account of the project instructions and observed implementation workflow. The instructions below are paraphrases, not verbatim quotations or a replacement for the original private transcript. The complete bounded visible transcript and actual original-language prompts are linked in README.md. The earlier event index remains as historical provenance. It is separate from the participant-model sessions used for benchmark evaluation.

## Project instructions used

1. Implement the complete benchmark and evaluation requirements, and check each milestone against the original specification rather than treating a working interface as completion.
2. Make L1鈥揕3 changes substantial, causal and visually clear. Move a work surface, stage its payloads on the floor, restore measured relative positions, preserve previous work and introduce a second consequential update.
3. Repair actual interpenetrations progressively. Maintain locked areas and previously completed repairs. Identify impossible soft preferences separately from feasible layout optimization.
4. Use actual native assets in model observations, executable outputs, geometric evaluation and review. For manipulation, preserve real terminal joint and object state, use distinct objects, release them and continue onward.
5. Give reconstruction tasks calibrated initial views and new observations after substantial target changes. Test stale-answer reuse, fixture-only updates and ignored observations.
6. Validate constraints, gold, solvability, collisions and shortcut rejection before interpreting model scores. Keep failed attempts and evidence of corrections.
7. Compare the two designated frontier models and use a separate auxiliary visual judge. Analyze concrete behaviors after contradictory feedback, not merely aggregate scores.
8. Test reward ordering, repeatability and attacks. Use an open-weight best-of-four probe, select by public reward and independently audit hidden quality. Do not equate selection with RL training.
9. Provide an English report, reproducible tables, self-contained task packages, actual gold/model trajectories, a public repository and an interactive site. Exclude private and unrelated information.
10. Prioritize simple complete changes, targeted regressions, evidence-backed explanations and the specification's substantive research questions over decorative additions.

## Evidence of iterative implementation

- Native byte persistence was corrected so source identity survives platform line-ending differences without accepting different programs. Retained provider responses were replayed rather than regenerated.
- Progressive repair distinguishes active work, preserved work and explicitly pending faults. Failure of a single fixed completion witness is not treated as a general impossibility proof.
- Independent package execution verified gold for all thirty instances. Public package preparation preserves runtime/assets/gold while adding scoped failure analyses and condition-aware replay arguments.
- A release-inspection regression showed that escaped JSONL text bypassed a language check. The inspector now decodes JSON and JSONL before checking publication content.
- A behavior regression showed that final submissions use a different observation shape from intermediate commitments. The analysis now records both and links unchanged submissions to preceding visible hard failures.
- A site regression showed that an implicit HTML body prevented appended study sections from appearing. The builder now uses an explicit available closing anchor and checks the output sections.
- Numerical rescoring and generation variability are labeled separately. The standalone reproduction command rebuilds the task/model table and can execute retained actions and gold through the included scorers.
- Report tables are generated from retained results; incomplete study coverage remains explicitly labeled. PDF pages are rendered and visually inspected after material updates.

## Redaction boundary

The primary session export is now `visible_session.jsonl`, not the older metadata-only event index. It retains ordered visible message bodies, tool inputs and outputs where safe. `ACTUAL_PROMPTS.jsonl` contains the retained actual user-message subsequence, with matching bodies and source hashes. The fixed snapshot boundary, content counts and explicit privacy omissions are documented in README.md and visible_manifest.json.

The original runtime snapshot remains local. Hidden reasoning, system/developer instructions, private correspondence, financial information, authentication material and confidential or unrelated content are not published. The narrower `events.jsonl` and selected English prompt translations remain historical supporting files rather than a claim of a verbatim original session.

## Actual code submission evidence

`selected_code/code_changes.jsonl` contains 273 actual English patch submissions joined to the event index by source event hashes. Workspace prefixes are removed from file headers. Submitted proposals include intermediate revisions and do not certify successful application; final runnable source is distributed in the task packages. Private or non-English patches are omitted rather than silently rewritten.

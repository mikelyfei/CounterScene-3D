Overview

CounterScene-3D evaluates whether an agent can turn observations into executable spatial decisions and revise them after consequential changes. Five task families combine layout, collision repair, multiview reconstruction, manipulation and unreliable feedback. Models operate on actual native assets, commit their actions, and preserve earlier accomplishments as new observations arrive.

Evaluation combines native geometry, explicit operation goals, state preservation and continuous kinematic checks where applicable. Auxiliary visual ratings and reward-optimization probes are reported separately from functional success.

Benchmark design

Each family contains two world seeds and three levels. L1, L2 and L3 contain one, two and three ordered operations. Later operations introduce a new decision and preserve prior work.

Task familyL1 / establishL2 / updateL3 / preserve and extend
A · Relocate and restoreRelocate the host; park its payloads at their original floor coordinates.Restore the payloads on the relocated host with the original relative offsets.Change a second work area while preserving the restored arrangement.
B · Progressive collision repairRepair the first released group of physical faults.Resolve newly released faults and preserve previous repairs.Finish the remaining repairs and satisfy the full final contract.
C · Changing-view reconstructionReconstruct the first target from its supplied views.Use new views to reconstruct a substantially changed target.Revise another changed region while preserving still-correct structure.
D · Stateful manipulationCalibrate, grasp the first object, place and release it, then move onward.Start from the actual terminal state and transfer a different object.Transfer another object while avoiding previously released objects.
E · Repair with misleading feedbackInspect physical evidence and repair the first active work zone.Handle a new fault group without undoing previous work.Complete the final repair and assess the misleading checker claims.

What the model receives and produces

Participant inputs

A task prompt, native-asset catalogue or mechanism specification, supplied images and public tool observations. Later stages release new work orders, views or actual physical state.

Executable outputs

One JSON tool action per turn. Placement tasks return a restricted Python build(public_params) program; manipulation returns joint keyframes and grasp/release events through the same program interface.

Exact prompts, input images and recorded feedback are available per instance and model on the Examples page. Gold programs and hidden scoring measurements are evaluator evidence, not participant inputs.

Evaluation

ObserveRead the current work order and inspect the actual state.
ConstructWrite a placement or motion program and use public tools.
ExecuteCommit the operation; valid mistakes remain in the history.
VerifyScore every stage against geometry, goals and preservation.

Strict success requires every required stage to pass. Reconstruction also requires hidden-view IoU ≥ 0.8 and every object centre within 0.05 m. Manipulation verifies continuous kinematic clearance and event semantics. Visual ratings cannot override functional failures.

This is a small development cohort. Geometric support does not imply dynamic stability; results do not establish held-out generalization or real-world robot reliability.
